# README skill/rules 一覧 更新スキル

## 目的

このリポジトリの README.md には、`skills/` 配下の各 skill と `rules/` 配下の各 rule を一覧化した
テーブルがある。skill や rule を追加・更新したのに README への反映を忘れると、他のエンジニアが
一覧から実体を辿れなくなる。このスキルは、skills/ と rules/ の実体（SKILL.md の frontmatter や
rule ファイルの内容）から一覧テーブルの行を機械的に組み立て、README.md に反映する。

## 対象範囲

- 追加・更新された skill / rule を README のテーブルに反映すること（行の追加・更新）が主目的。
- skill / rule の削除に伴う行削除は対象外。ユーザーから明示的に削除を依頼された場合のみ、その指示
  に従って該当行を削除してよい。
- README の一覧テーブル以外の記述（「利用方法」「格納ルール」等のセクション）は変更しない。
- `skills/`, `rules/` 以外のディレクトリ・ファイル（例: `docs/`, `.github/` 等）の追加・変更は
  対象外。このスキルはそれらを検知・反映する仕組みを持たない。誤って呼ばれた場合は、手順1の
  とおり「対象が見つからない」旨を報告し、README には一切手を加えない。

## 手順

### 1. 対象を特定する

- `git status --short skills/ rules/` と `git diff -- skills/ rules/` を確認し、追加・変更された
  ファイルを特定する。
- ユーザーが対象の skill/rule 名を明示した場合はそれを優先する。
- 特に指定がなく「一覧を最新化して」のような依頼の場合は、`skills/*/SKILL.md` と `rules/*.md` の
  全件を洗い出し、README 側のテーブルと突き合わせて過不足（未掲載・内容の乖離）がないか確認する。
- `skills/`, `rules/` に該当する変更が見つからない場合（他のディレクトリ・ファイルのみが変更されて
  いる場合を含む）は、その旨をユーザーに報告して終了する。README.md には一切変更を加えない。
  「一覧テーブルは既に最新です」と「そもそも対象の変更が見当たりません」は区別して伝える。

### 2. skill の情報を抽出する

各 `skills/<name>/SKILL.md` の frontmatter（`name`, `description`）を読む。

`description` は通常「①何をするか」と「②どんな発話・状況で使うか」の2つの要素で構成されている
（`skills/auto-commit-msg/SKILL.md` を参照）。これを以下のように2列に振り分ける：

- **説明**列：①に相当する一文。「〜する」で終わる簡潔な要約にする。
- **利用場面**列：②に相当する一文。「〜と言ったとき」「〜な場合に使用する」に該当する部分を使い、
  ユーザー発話の引用（「」で囲まれた部分）があればできるだけそのまま残す。

description の文が綺麗に2分割できない場合は、無理に機械的に割らず、趣旨を保ったまま自然な日本語で
要約してよい。

### 3. rule の情報を抽出する

`rules/<name>.md` は frontmatter を持たず、見出し＋本文のみで構成される想定（`~/.claude/rules/` の
既存ファイル群と同様の形式）。ファイル冒頭の見出しと最初の段落・表から、以下を1文程度で要約する：

- **説明**列：そのルールが何を規定しているか。
- **適用対象**列：どんな実装・ファイル種別・場面に適用されるか（例：「Swift の命名・インデント規約」
  「SwiftUI View 実装全般」）。

### 4. README.md のテーブルを更新する

**skill 一覧**（`| skill 名 | 説明 | 利用場面 |`）:

- 対象 skill の行が既に存在する場合（`[skill名](skills/skill名/SKILL.md)` のリンクで判定）、
  説明・利用場面の内容を最新化する。
- 存在しない場合、テーブル最終行の後・「skill を追加したら、この表に1行追記してください。」という
  注記文の前に新規行を追加する。

**rules 一覧**:

- README には現在「現時点で `rules/` は空です。今後ルールを追加した際は、skill 一覧と同様に
  このセクションへ一覧テーブルを追加していきます。」という文しかない。**最初のルールを追加する
  ときは**、この文をテーブルヘッダ＋最初の行に置き換える：

  ```markdown
  | ルール名 | 説明 | 適用対象 |
  | --- | --- | --- |
  | [rule名](rules/rule名.md) | ... | ... |

  ルールを追加したら、この表に1行追記してください。
  ```

  （skill 一覧セクション末尾の「skill を追加したら〜」という注記と対になる文言にする）

- 2件目以降は、skill 一覧と同じ要領で既存テーブルへの行の追加・更新を行う。

### 5. 差分を提示する

更新後、変更箇所（追加・更新した行）をユーザーに分かるように示す。README 全体を貼り直すのではなく、
どの行が増えた／変わったかを明示する。

## 参考：既存テーブルのフォーマット

skill 一覧の例（`README.md` より）：

```markdown
| skill 名 | 説明 | 利用場面 |
| --- | --- | --- |
| [auto-commit-msg](skills/auto-commit-msg/SKILL.md) | Conventional Commits 形式のコミットメッセージを自動生成する | 「コミットして」「commit」「変更を保存」等と言われたとき |
```
