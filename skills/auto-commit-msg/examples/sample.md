# auto-commit-msg スキル - 動作例

## 例1: 通常のブランチでのコミット

ユーザー: 「ログイン機能を追加したのでコミットして」

→ `git diff --staged` で変更を確認後、以下のようなメッセージでコミット:

```
feat(auth): ユーザーログイン機能を追加

- メールアドレスとパスワードによる認証を実装
- セッション管理はJWTトークンを使用
- パスワードはbcryptでハッシュ化
```

## 例2: mainブランチでのコミット（保護機能）

ユーザー: 「修正内容をコミットして」（mainブランチ上で実行）

→ 以下の警告と選択肢を表示:

```
⚠️  **警告**: mainブランチに直接コミットしようとしています。
通常は feature/ または bugfix/ ブランチでの開発をお勧めします。

現在のブランチ: main

どうしますか？

1. 新たなブランチを作成し、そこでコミットします
2. 現在のmainブランチにコミットします
```

→ ユーザーが「1」を選択した場合:
- 新しいブランチを作成（例: `fix/greeting-text`）
- そのブランチに切り替え
- コミットを実行

→ ユーザーが「2」を選択した場合:
- mainブランチのまま通常のコミット手順を進行

## 例3: 単一ファイル修正（scope 提案）

ユーザー: 「グリーティングテキストを修正してコミット」（ContentView.swift のみ修正）

→ `git diff --staged` で変更を確認後、UI コンポーネントの修正と判定し scope を提案：

```
📋 **scope の提案**: この変更は UI コンポーネント（ContentView.swift）の修正です。
scope を「ui」として適用しますか？

1. scope「ui」を適用：`style(ui): グリーティングテキストの感嘆符を修正`
2. scope なしで進める：`style: グリーティングテキストの感嘆符を修正`
```

→ ユーザーが「1」を選択した場合：
```
style(ui): グリーティングテキストの感嘆符を修正
```

→ ユーザーが「2」を選択した場合：
```
style: グリーティングテキストの感嘆符を修正
```
